# v1.3.1 — Demo Execution Bridge (paper forward-testing)

**Date:** 2026-07-09
**Scope:** Demo-only forward-testing bridge so paper signals can be tested against
realistic demo fills, spreads, slippage, and rejections. **No live trading, no
real-money execution, ALLOW_LIVE_ORDERS stays false, broker_mode hard-locked to
`demo`.**

## Safety invariants (test-enforced)
- `broker_mode` is DB-locked to `'demo'` via `CHECK (broker_mode = 'demo')` on
  both `DemoExecutionOrder` and `ExecutionControl`. SQLite refuses any live row.
- `run_execution.py` refuses if `allow_live_orders` is true or `broker_mode != 'demo'`.
- Secrets are **never** stored: schema has no password/secret/token/api_key columns;
  only `raw_response_redacted_json` is kept (redacted by `redact()`). Credentials come
  from env vars only (`DERIV_MT5_*`, `OANDA_PRACTICE_*`).
- Every demo order **must** carry a `stop_loss` and `take_profit` (`NOT NULL`) and
  pass the deterministic risk engine (`src.signals.risk_check`).
- No random exploration: every order is derived from a parent paper `Signal`; a
  missing signal is rejected. AI-generated trades go through the same gate.
- Max open demo trades enforced (`ExecutionControl.max_open_demo_trades`, default 5).
- Kill switch (`ExecutionControl.kill_switch`) refuses all orders when engaged.

## Data model (schema.sql)
- **DemoExecutionOrder** — id, signal_id, broker, broker_mode(='demo'),
  symbol, side, requested/filled entry, stop_loss, take_profit, units,
  requested/filled_at, status, rejection_reason, spread_at_entry, slippage,
  raw_response_redacted_json.
- **ExecutionJournal** — demo vs paper entry/pnl, slippage, spread, latency,
  was_execution_acceptable, lesson_json.
- **ExecutionControl** — singleton (id=1): kill_switch, broker_mode(='demo'),
  max_open_demo_trades. Seeded by migration.

## Engine (Python, engine/src/execution/)
- `adapter.py` — `ExecutionAdapter` ABC + `DemoOrderRequest`, `AccountInfo`,
  `PriceQuote`, `Position`, `OrderStatus`, `redact()` (credential scrubber).
- `guards.py` — `run_pretrade_guards()`: source-agnostic deterministic gate
  (live off, SL+TP required, risk_check, paper signal required, max open, kill switch).
- `mock_adapter.py` — deterministic in-memory demo broker (default). Reproducible
  fills from a fixed spread/slippage; never touches network.
- `deriv_mt5.py` / `oanda_practice.py` — real demo adapters that **raise at
  construction** when credentials are missing (fail-loud, bridge stays disabled).
  OANDA targets the practice host only.
- `factory.py` — `build_adapter(name)` defaults to `mock`; real adapters only when
  creds present (`fail_loud=False` falls back to mock).
- `run_execution.py` — CLI: `check | demo-order | update | journal | kill-switch`.

## Env vars needed for real demo brokers (optional)
- Deriv MT5 demo: `DERIV_MT5_LOGIN`, `DERIV_MT5_PASSWORD`, `DERIV_MT5_SERVER`.
- OANDA practice: `OANDA_PRACTICE_API_KEY`, `OANDA_PRACTICE_ACCOUNT`.
- Without these, the bridge uses the mock adapter and the real adapters stay disabled.

## How to run demo mode
1. `npm run db:migrate` (creates execution tables + control singleton).
2. `npm run execution:check` — confirm paper_only/allow_live_orders/broker_mode + mock.
3. `npm run monitor:signals` (ensure paper signals exist).
4. `npm run execution:demo-order -- --signal-id N` — forward-test signal N via mock.
5. `npm run execution:update` — refresh open-order status.
6. `npm run execution:journal` — review paper-vs-demo comparison rows.
7. `npm run execution:kill-switch --on` — emergency halt; `--off` to re-arm.
8. Open the **Demo Execution** page for the live dashboard.
