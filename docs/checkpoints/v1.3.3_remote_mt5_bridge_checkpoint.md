# v1.3.3 — Tailscale Remote MT5 Bridge (VPS → Windows PC)

**Date:** 2026-07-11
**Scope:** Let Aether Forex Lab on the Linux VPS drive an MT5 **demo** account
running on the Windows PC over a private Tailscale link. The VPS never holds
MT5 credentials — only `REMOTE_MT5_BRIDGE_URL` + `REMOTE_MT5_BRIDGE_TOKEN`.

## What was built

### 1. PC bridge package — `remote-mt5-bridge/`
- `server.py` — FastAPI bridge, binds **127.0.0.1:8787** only, exposed privately
  via `tailscale serve`. Bearer-token auth, demo-only (`_ensure_demo_account`
  rejects LIVE `trade_mode`), own `BRIDGE_KILL_SWITCH`, SL/TP required, endpoints:
  health / account / symbols / quote / dry-run / place-demo-order / positions /
  order-status / kill-switch.
- `requirements.txt`, `.env.example` (MT5 creds live **only** here, PC side),
  `README.md` (Windows setup), `TAILSCALE.md` (route docs).

### 2. VPS adapter — `engine/src/execution/remote_mt5_bridge.py`
- Thin HTTP client. Bearer auth, configurable timeout + retry, **fail loud** if
  URL/token missing or unreachable, **rejects non-demo** bridge responses,
  **no fallback to mock** for real-demo commands. Never reads `MT5_LOGIN/PASSWORD/SERVER`.

### 3. Wiring
- `factory.py` — registers `remote_mt5`; `PRIMARY_DEMO_BROKER` may be `remote_mt5`.
- `capabilities.py` — `remote_mt5_capability()` (URL+token presence only).
- `run_execution.py` — commands: `remote-mt5-check`, `remote-mt5-symbols`,
  `remote-mt5-quote`, `remote-mt5-dry-run`, `remote-mt5-order`. They persist a
  redacted `RemoteBridgeStatus` row (no token/creds).
- `schema.sql` — new `RemoteBridgeStatus` table (no secret columns).
- `app/lib/db.ts` — `remoteBridgeStatus()`, `remoteBridgeHistory()`.
- `package.json` — 5 npm scripts.
- `app/broker-demo/page.tsx` — Remote MT5 Bridge section (reachable, Tailscale
  URL configured, PC bridge mode, bridge kill-switch, latest quote, symbol map,
  open positions).

## Safety locks (verified)
- Demo only: bridge refuses LIVE account; VPS rejects non-demo responses.
- URL/token missing → fail loud (tests: missing URL, missing token, invalid token, unreachable).
- VPS kill switch (observe_only / `can_place_real_demo()==False`) blocks orders.
- PC bridge kill switch blocks orders independently.
- Every order needs an approved paper Signal + SL + TP; routes through the same
  hard-gated `_place_real_demo` path.
- `RemoteBridgeStatus` stores no `password|secret|api_key|token|login|mt5`.
- No MT5 credentials referenced anywhere on the VPS.
