# v1.3 — Market Trend Intelligence layer

**Date:** 2026-07-09
**Scope:** Add a probabilistic, evidence-based market-trend intelligence layer to
Aether Forex Lab. Research/observability only — **no live execution, no broker
code, locked scoring weights untouched.**

## Safety invariants (all enforced by tests)
- No live execution / no broker / no order-sizing code anywhere in the trend layer.
- `run_trends.py` refuses to run unless `paper_only: true` and `allow_live_orders: false`.
- Locked walk-forward strategy scoring is **not** modified — the trend layer only
  *reads* `StrategyScore`/`BacktestRun` as regime-history evidence for confidence.
- No certainty language in engine outputs, UI, or scripts (regex-guarded in tests).
- Every prediction carries a **required** invalidation price (`NOT NULL` + loader guard).
- Predictions are **stored before outcome**; the review loop fills only outcome
  fields and can **never** overwrite the original prediction (test-enforced on the
  UPDATE SET clause).
- `uncertain` is a first-class, encouraged label when signals conflict.

## Data model (app/schema.sql)
- **MarketTrendSnapshot** — point-in-time regime read per symbol/timeframe:
  regime (trend|range|volatile|uncertain), direction (bullish|bearish|sideways|uncertain),
  trend_strength, momentum_score, volatility_score, confidence_score, best_strategy,
  invalidation_price, reasons_json, risks_json. `UNIQUE(symbol,timeframe,detected_at)`.
- **TrendPrediction** — probabilistic forecast per horizon (1h|4h|1d) with
  entry_context_json + required invalidation_price; nullable outcome fields
  (outcome_price, outcome_direction, was_correct, reviewed_at) populated later.
  `UNIQUE(symbol,timeframe,prediction_time,horizon)` → idempotent re-ingest.
- **TrendReviewLesson** — stored misses: predicted vs outcome, which naive
  baseline(s) beat us, and the lesson text.

## Engine (Python)
- **engine/src/trend.py** — regime classification from EMA slope/separation, ATR-based
  volatility vs its rolling median, and recent swing structure. `score_directions`
  emits a probability distribution over {bullish,bearish,sideways,uncertain} that sums
  to 1.0; conflict/weak-structure forces `uncertain`. `assign_confidence` scales with
  strategy history in a comparable regime (low + `n/a` best_strategy when no history).
  `invalidation_price` sits below price for bullish reads, above for bearish, banded
  for uncertain — always non-null.
- **engine/run_trends.py** — per enabled forex/metal symbol: load cached/live prices
  (fail-loud on data error, never fabricated), build a snapshot, read regime history
  from the app DB, emit one prediction per horizon (entry_price, prev_close,
  ema_slope_sign for baseline comparison), write `engine/results/trends.json` (gitignored).

## App pipeline (Node)
- **scripts/trend_ingest.mjs** — idempotent loader: snapshots upsert on
  (symbol,timeframe,detected_at); predictions upsert on
  (symbol,timeframe,prediction_time,horizon) refreshing only still-pending rows,
  skipping any prediction lacking an invalidation price. No outcome fields on insert.
- **scripts/review_trends.mjs** — reviews predictions whose horizon elapsed against
  the current price; compares to 3 naive baselines (a) follow previous candle,
  (b) assume no change, (c) follow EMA trend; writes outcome fields only and stores
  a TrendReviewLesson on misses. Never edits the original prediction.
- **lib/db.ts** — accessors: latestTrendSnapshots, latestPredictionFor,
  trendAccuracyBy([...]), recentTrendLessons.
- **app/market-trends/page.tsx** — dashboard: direction, confidence, regime, best
  strategy, invalidation level, latest 1d outcome; accuracy by symbol and horizon;
  review lessons table; paper-only / no-certainty banner.

## Wiring
- `package.json`: `trends:detect`, `trends:ingest`, `review:trends`.
- `daily_loop.mjs`: after `score:strategies` → `trends:detect` → `trends:ingest`,
  and `review:trends` after `review:outcomes` (all via runStep → SchedulerRunLog).
- `Nav.tsx`: added "Market Trends".
- `db_migrate.mjs`: creates trend tables + guarded in-place rebuild adding the
  TrendPrediction UNIQUE constraint (row-preserving, de-duping).

## Notes / limitations
- Trend reads are deliberately low-conviction until strategy history accumulates per
  regime; this is by design (evidence-based, no false confidence).
- Baseline comparison inputs (prev_close, ema_slope_sign) are stored in entry_context
  at prediction time so reviews are apples-to-apples.
